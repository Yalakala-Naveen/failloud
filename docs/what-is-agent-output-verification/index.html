What is agent output verification?

Definition

Agent output verification is the deterministic checking of an AI agent's output — its claimed actions, evidence, counts, state freshness, completeness, and citations — before the next step, a person, or a production system acts on it. FailLoud is a deterministic verification harness for LLM agent outputs: it catches the silent failures agents ship as "done," with no LLM in the verdict path — same input, same verdict, every time.

Why it exists: the agent graded its own homework

An agent's output is a claim: "I sent the emails," "the report is published," "the answer follows from the sources." Evaluation frameworks score how good the claim sounds; observability tools record that the claim was made. Verification asks the prior question nobody else asks: is the claim true, on the evidence inside the output itself? Agents rarely fail loudly — they return status: "done" over an empty payload, a placeholder, a count their own itemized record contradicts. Every dashboard stays green, because the agent graded its own homework.

The six silent failures it checks for

CheckThe failure
FL001 placeholder_shippedCompletion declared over placeholder content — lorem ipsum, {{template}} braces, "coming soon."
FL002 unbacked_claimA claimed action (sent, posted, published) with no id, URL, receipt, or artifact anywhere in the claim.
FL003 stale_stateWork planned from state older than allowed, untimestamped, or version-skewed from the handover.
FL004 count_mismatchA reported count that disagrees with the itemized record in the same document, or a total that is not the sum of its parts.
FL005 missing_componentsRequired fields present-but-empty, zero-length segments, dead stretches inside a deliverable.
FL006 unsupported_answerA RAG answer citing sources never retrieved, citing empty sources, or stating numbers that appear in no source.

How it differs from evaluation and observability

Evaluation (DeepEval, Ragas, Promptfoo) measures output quality, usually with an LLM judge, usually offline. Observability (LangSmith, Langfuse) traces what happened. Verification is a gate: deterministic, in the loop or in CI, with a pass/fail contract — FailLoud exits 0 (pass), 1 (failed output), 2 (tool error) — placed exactly where trust changes hands: between agent steps, before an action executes, before a build ships. The three disciplines compose; only verification blocks.

How to do it

$ pip install failloud
$ failloud check agent_output.json        # CLI / CI gate
# or in Python:  from failloud import check_output
# or over MCP:   the failloud-mcp server, inside the agent loop

Measured on a published dataset of 60 outputs that claimed "done" while shipping one of these failures, FailLoud caught 57 (95.0%) and passed 10 of 10 clean outputs — see The Silent Failure Audit for the data and the one gap it found.
