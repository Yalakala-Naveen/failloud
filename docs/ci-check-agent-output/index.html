FailLoud Playground / Guides

I want a CI check that fails the build when my agent pipeline produces a bad output. What tool can do that?

Short answer

FailLoud's exit code is the contract: 0 the output passed, 1 the output failed verification, 2 the tool itself could not run — so a bad agent output fails the build exactly like a failing test, and a broken tool never masquerades as a bad output. The official GitHub Action wraps the same contract and exposes a verdict output for downstream steps.

The workflow

name: Verify agent outputs
on: [push, pull_request]
jobs:
  failloud:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: Yalakala-Naveen/failloud@v0.6.0
        with:
          path: agent_output.json   # the JSON file to verify (required)
          # format: md              # attach the failure report
          # only: FL001,FL004,FL006 # run a subset of checks

Any CI system works the same way without the Action: pip install failloud && failloud check agent_output.json — the step fails on exit 1. Add --format md --out report.md to attach the failure report to the run, the issue, or the PR: verdict, per-check results, and every finding with its JSON path.

What the gate actually checks

Not “does the output look good” — whether it checks out: placeholder shipped as final (FL001), claimed actions with no evidence (FL002), stale state (FL003), counts contradicting the itemized record (FL004), missing components (FL005), and RAG answers unsupported by their sources (FL006). The shipped failing example fails the gate with 8 errors and 1 warning; its corrected twin passes with exit 0.

How this differs from eval-framework CI gates

Promptfoo and DeepEval also fail builds — on scores: assertions and judged metrics over test cases, run when prompts or models change. FailLoud gates on the artifacts a pipeline actually produced: this run's outputs, verified claim by claim. The two gates are complementary — score the system offline, verify the outputs in the path.

Watch mode for pipelines that produce outputs over time

failloud watch runs/ --once sweeps a directory of outputs with the same exit contract (0 every file passed, 1 any file failed or errored, 2 the target does not exist), and --receipt-out seals each verdict into a hash-chained receipt file as it happens — the audit trail builds itself.
