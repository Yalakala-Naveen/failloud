The Silent Failure Audit: how many "done" agent outputs are lying?

Short answer

FailLoud is a deterministic verification harness for LLM agent outputs — it catches the silent failures agents ship as "done." In this audit, 60 synthetic agent outputs claimed done while shipping exactly one silent failure each. FailLoud caught 57 of them (95.0%), and 10 of 10 genuinely clean outputs passed with no false alarms. The dataset, the generator script, and every per-case verdict are published — every number on this page regenerates from one command.

Method, in one paragraph

The audit builds 70 synthetic agent outputs deterministically — no randomness, no hand-picked results. Sixty are defective: 10 per silent-failure pattern (FL001–FL006), each claiming done, each carrying exactly one planted defect, skinned across 10 everyday scenarios — a newsletter send, a ticket export, an invoice batch, a social post, a CRM sync, a report publish, a podcast cut, an inventory update, release notes, meeting-notes distribution. Ten are clean controls that claim done and are, in fact, complete. Every case runs through failloud check_output with the default configuration; a defective case counts as caught when its pattern's check fires at error severity.

The one gap, reported as found

All three FL003 misses are the same variant: state handed over with no freshness timestamp at all. FailLoud raises a warning for unmeasurable freshness — not an error — so those three runs still pass overall. The stale-timestamp and version-skew variants fail as errors, 7 of 7. An audit that hides its misses is marketing; this one publishes them, because the warning-versus-error line for untimestamped state is a real design question the data should inform.

Reproduce it

$ git clone https://github.com/Yalakala-Naveen/failloud
$ cd failloud/audits/silent-failure-audit
$ PYTHONPATH=../../src python run_audit.py

The dataset (cases.json), per-case verdicts (results.json), and the summary (results.md) live in audits/silent-failure-audit in the repository. Quote it as: "57 of 60 (95.0%) silent-failure outputs caught; 10 of 10 clean outputs passed."
