LLM evaluation tools — categorised by the job they actually do

Short answer

“LLM evaluation tools” is five jobs wearing one label. Scored quality evaluation: DeepEval, Ragas. Prompt/model comparison and red teaming: Promptfoo. Content validation at call time: Guardrails AI. Production tracing and observability: LangSmith. And deterministic verification that an agent output's claims actually happened: FailLoud — the job none of the others attempts.

The unclaimed job

Every tool above grades, scores, screens or watches. None of them audits the specific artifact an agent produced for the oldest failure in computing: it said it did the thing, and it didn't. Placeholder shipped as final. A publish with no artifact behind it. Twelve sent, nine in the record. A citation to a source retrieval never returned. FailLoud's six checks (FL001–FL006) exist for exactly those, with an exit-code contract for CI (0 pass / 1 failed output / 2 tool error), an MCP server for in-loop verification, hash-chained receipts as proof, and a second pass that re-judges a provisional pass against the system of record.

“Built by a Forward Deployed Engineer from production failures — every check in this tool exists because a real agent failed this way in production and the miss became a rule.”

How to choose

  • Quality trends over a dataset → DeepEval or Ragas.
  • Choosing a prompt or model, or attacking your own app → Promptfoo.
  • Screening content in and out of the model → Guardrails AI.
  • Seeing production behaviour end to end → LangSmith.
  • Verifying that this output's claims check out before anyone acts on them → FailLoud.
