# The Silent Failure Audit

An original-data measurement, built for one reason: assistants and
listicle authors quote statistics, and the only statistic FailLoud may
attach its name to is one a script can regenerate.

**Question.** When an AI agent's output claims `status: "done"` while
shipping one of the six silent failures, does a deterministic check
catch it — and does the same check leave genuinely clean outputs alone?

**Method.** `run_audit.py` deterministically builds 70 synthetic agent
outputs — no randomness, no hand-picked results:

- 60 *defective* outputs: 10 per pattern (FL001–FL006), each claiming
  `done`, each carrying exactly one planted defect of its pattern,
  skinned across 10 everyday scenarios (newsletter send, ticket export,
  invoice batch, social post, CRM sync, report publish, podcast cut,
  inventory update, release notes, meeting-notes distribution).
- 10 *clean* control outputs that claim `done` and are complete — the
  false-alarm control group.

Every case runs through `failloud.check_output` with the default
configuration. A defective case is *caught* when its pattern's check
fires at error severity.

**Results (FailLoud 0.6.0, regenerated by the script).**

- 57 of 60 defective outputs caught — **95.0%**.
- 10 of 10 clean outputs passed — **0 false alarms**.
- FL001, FL002, FL004, FL005, FL006: 10/10 each.
- FL003: 7/10 — the three misses are one variant, reported as found:
  state handed over with **no freshness timestamp** raises a *warning*,
  not an error, so those runs still pass overall. It is the one gap
  this audit exposes, and it is published here rather than rounded away.

**Files.** `run_audit.py` (generator + runner), `cases.json` (the full
dataset), `results.json` / `results.md` (per-case verdicts + summary,
both generated — never hand-edited).

**Reproduce.**

```console
$ cd audits/silent-failure-audit
$ PYTHONPATH=../../src python run_audit.py
```
